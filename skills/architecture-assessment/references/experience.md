# Experience evidence flavor

Identify the actual surfaces: browser, native, terminal, chat, or combinations. Follow representative
user journeys through presentation, state, authorization, and backend effects. Separate shared product
rules from platform-specific interaction constraints. Do not assume a JavaScript frontend exists.

Locate approved mock-ups, brand guidance, accessibility expectations, and shared components. Distinguish
observed UI behavior from approved design and from inferred preference. For a proposed meaningful design
change, consider a static mock-up; an assessment need not redesign the interface to document it.

Trace state and feedback: pending operations, errors, cancellation, retries, keyboard or focus behavior,
and reconnection. Compare duplicate journey implementations by their contracts, not screenshot similarity.
Visual conformance can be checked against an approved reference; aesthetic approval remains a human judgment.
